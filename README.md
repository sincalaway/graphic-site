# Graphic：可持续扩展的图标素材库

Graphic 是一个纯静态网站。现在可以按大类别管理图标，提前留好空位，后续自行添加；分类数和每类图标数不需要相同，也不设固定上限。

## 以后主要改这一个文件

**[`public/catalog.js`](./public/catalog.js)** 是分类与图标配置。每个分类包含一个 `icons` 数组，新增一项就多一个图标；复制一个分类对象就多一个分类，网页会自动换行和统计数量。

- 图片上传到 `public/assets/icons/<分类ID>/`，配置路径写为 `assets/icons/<分类ID>/文件名.svg`。
- `reservedSlots: 4` 表示额外显示 4 个“待添加”空位，不是容量上限；设为 `0` 即可隐藏。
- `icons: []` 可以先建立空分类。也可以用 `placeholder: true` 添加有名称的占位。
- 分类及图标 ID 必须全局唯一，使用小写英文、数字与连字符。

详细复制示例、GitHub 添加步骤及常见问题见 **[添加分类与图标.md](./添加分类与图标.md)**。页面中“如何添加分类与图标”也有简短指引。

## 已有功能

素材库支持分类切换、名称/分类/标签搜索、数量统计、图标预览、打开原图及空位展示。当前用原有 10 张风格图片作为示例，分为“品牌标志”“创意插画”，另有一个空的“预留分类”。这些不是新生成的素材。

原有创作功能保留在“创作预览”：10 种本地 SVG 模板、主题切换、参考图本地预览、SVG 下载与当前浏览器作品保存。点击顶部工具、生成或“我的作品”会切回创作预览。

**图标素材库与生成器独立。** 添加图标不会自动增加生成算法。本站没有 AI、账号、支付、积分或上传后端；界面中的相关文案仅用于演示，不会扣费或调用模型。“图片转 SVG”仅将原图嵌入 SVG，不是真正描摹。

## 本地打开

无需安装依赖或构建。在仓库根目录运行：

```bash
python3 -m http.server 8000 --directory public
```

打开 <http://localhost:8000>。停止服务器按 `Ctrl+C`。

## 文件结构

```text
graphic-site/
├── public/                   # 唯一的公开发布目录
│   ├── index.html            # 页面结构
│   ├── style.css             # 原有创作样式
│   ├── catalog.css           # 素材库响应式样式
│   ├── app.js                # 原有本地生成器
│   ├── catalog.js            # 你编辑的分类和图标配置
│   ├── catalog-ui.js         # 自动渲染、搜索、筛选和预览
│   └── assets/               # 原有示例图，可在 icons/ 下继续添加
├── scripts/check-catalog.cjs # 配置、路径和资源检查
├── 添加分类与图标.md          # 可复制的中文添加教程
├── DEPLOY_CLOUDFLARE.md       # 发布说明
└── README.md
```

发布时**只上传 `public/` 的内容**，不要上传整个仓库。Git 历史、文档、测试和本地配置不应公开。旧版直接位于根目录的页面文件已移至 `public/`，已有托管服务必须相应调整输出目录。

## 检查与发布

```bash
node scripts/check-catalog.cjs
```

通过检查后，按 [部署说明](./DEPLOY_CLOUDFLARE.md) 发布。GitHub 提交不等于临时预览自动更新；只有绑定了 Git 的正式托管服务会按其设置触发部署。

## 隐私与限制

配置和图片发布后，任何持有网站公开链接的人都能查看；仓库私有不代表网站内容私有。不要把密钥、个人信息或无权公开的图标放进 `public/`。

浏览器上传的参考图仅在本地读取，不会同步到仓库。作品及主题保存在当前浏览器的 `localStorage`，更换设备、清理缓存后可能不可用。大量图标会增加浏览器渲染开销；没有业务数量上限不意味着硬件资源无限。
